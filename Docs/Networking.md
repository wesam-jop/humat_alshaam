# الشبكة

## لماذا Unity Transport مباشرة؟

اخترت `com.unity.transport 2.5.3` مع بروتوكول صغير مكتوب في `Networking/Protocol/NetMessages.cs` بدل Netcode for GameObjects:
- الخادم صاحب القرار، والعميل يرسل أوامر إدخال فقط، فاحتجت التحكم الكامل في التكة والتنبؤ وإعادة التشغيل بنفس `PlayerMotor`.
- لا يحتاج حساباً سحابياً ولا مفتاح خدمة، ويعمل على Windows وAndroid وiOS، وحزمته صغيرة.
- يحتوي `SimulatorPipelineStage` لمحاكاة التأخير وفقد الحزم في الاختبارات.
- `ProtocolInfo.ProtocolVersion` يُفحص في المصافحة، والعميل غير المتوافق يُرفض برسالة عربية.

## الرسائل

| الرسالة | الاتجاه | القناة | المحتوى |
|---|---|---|---|
| `Hello` | عميل ← خادم | موثوقة | إصدار البروتوكول، معرف الملف المحلي، الاسم، رمز مصادقة (فارغ للضيف) |
| `Welcome` | خادم ← عميل | موثوقة | معرف اللاعب الذي عيّنه الخادم، معدل التكة |
| `Reject` | خادم ← عميل | موثوقة | السبب: إصدار غير متوافق، الجلسة ممتلئة، استُبدل باتصال جديد |
| `Input` | عميل ← خادم | غير موثوقة | آخر 4 أوامر (تكرار ضد فقد الحزم) |
| `Snapshot` | خادم ← عميل | غير موثوقة | كل اللاعبين بحالتهم الكاملة + آخر أمر عالجه الخادم لكل لاعب |
| `Shutdown` | خادم ← عميل | موثوقة | المضيف يغلق الجلسة |

- كل أمر مربوط بالاتصال الذي أرسله، والخادم يطبّق `Sanitized()` (لا سرعة أكبر من 1، لا NaN).
- اللقطة كل تكتين (30 في الثانية).
- العميل يتنبأ بلاعبه، ويقارن اللقطة بتاريخ تنبؤه. إذا زاد الفرق عن 2 سم يرجع لحالة الخادم ويعيد تشغيل الأوامر التي لم يعالجها الخادم، ويُخفي التصحيح بتنعيم بصري قصير.
- اللاعبون البعيدون يُعرضون متأخرين 0.1 ث مع استيفاء بين لقطتين.
- الإيقاف المؤقت في الشبكة يرسل أوامر محايدة فقط، والجلسة تستمر للآخرين. في الأوفلاين يوقف المحاكاة.

## الأخطاء المعالجة

| الحالة | ما يحدث |
|---|---|
| عنوان أو منفذ غير صالح | رسالة فورية في القائمة، والنموذج يبقى مفتوحاً |
| لا يوجد مضيف | انتهاء المهلة بعد محاولات الاتصال (افتراضياً 5 × 1 ث) ثم رسالة |
| إصدار غير متوافق | رفض من الخادم ورسالة «حدّث اللعبة» |
| انقطاع العميل | الخادم يحذف لاعبه فوراً (خروج نظامي) أو بعد مهلة 4 ث (انقطاع) |
| إغلاق المضيف | رسالة `Shutdown` ثم «أغلق المضيف الجلسة» والعودة للقائمة |
| موت عملية الخادم | «انقطع الاتصال بالخادم» بعد مهلة الانقطاع ثم القائمة |
| إعادة انضمام نفس الملف | الخادم يحذف النسخة القديمة قبل إنشاء الجديدة |

## الإعدادات

بالترتيب، والأخير يغلب:
1. `Assets/Game/Configuration/Resources/Adventure3D/NetworkProfile.asset`
2. ملف `adventure3d-settings.json` بجانب `Adventure3D.exe` أو في `persistentDataPath`:
   ```json
   { "onlineServerAddress": "play.example.com", "lanAddress": "192.168.1.20", "port": 7777, "maxPlayers": 8 }
   ```
3. وسائط سطر الأوامر: `-mode offline|host|client|server`، `-address`، `-port`، `-simLatency`، `-simJitter`، `-simLoss`، `-protocol`، `-profile`، `-settings <path>`.

## الأونلاين

الخادم المستقل هو نفس الملف التنفيذي مع `-batchmode -nographics -mode server`. اختُبر كعملية منفصلة مع عميلين على نفس الجهاز (localhost). اختبار الإنترنت العام يحتاج خادماً له عنوان عام ومنفذ UDP مفتوح، وهو بند مستقل لم يُنفّذ. وحدة «Windows Dedicated Server» غير مثبتة في المحرر، لذلك لا يوجد بناء Server Subtarget منفصل. التشغيل بلا رسوم يتم عبر `-batchmode -nographics`.
